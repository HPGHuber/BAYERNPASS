# Roadmap

Die Roadmap ist ein Vorschlag und wird anhand von Pilotpartnern, rechtlicher Prüfung und Nutzerfeedback angepasst.

## Phase 0 – Fundament (jetzt)
- [x] Öffentliches Repository angelegt
- [x] Vision und Leitprinzipien dokumentiert
- [x] Architektur- und Datenschutzleitlinien erstellt
- [x] Erster statischer Portal-Prototyp
- [ ] Governance, Lizenz und Maintainer-Modell festlegen
- [ ] Anforderungen mit Bürgerinnen, Kommunen und Barrierefreiheits-Expertinnen validieren

## Phase 1 – Klickbarer MVP
- [ ] Portal-Frontend mit Startseite, Diensten und Beteiligungsbereich
- [ ] Beispiel-Mandant „München“ mit ausschließlich fiktiven Daten
- [ ] OIDC-Testintegration mit lokalem Identity-Provider
- [ ] CONSUL-Demo in isolierter Testumgebung
- [ ] OpenAPI-Schnittstellenentwurf
- [ ] Automatisierte Tests und CI

## Phase 2 – Begrenzter Pilot
- [ ] Einen konkreten kommunalen Beteiligungsprozess auswählen
- [ ] Zuständigkeiten und Rechtsgrundlage klären
- [ ] Datenschutz-Folgenabschätzung prüfen/erstellen
- [ ] Barrierefreiheit und analoge Alternativen sicherstellen
- [ ] Externe Sicherheitsprüfung vor realen Nutzerdaten
- [ ] Evaluation anhand veröffentlichter Kriterien

## Phase 3 – Interoperabilität
- [ ] BayernID/EUDI-Wallet-Integration nur mit offizieller Freigabe
- [ ] HEAVENKEY-Passkey- und Recovery-Flows
- [ ] Föderierte Mandanten und standardisierte APIs
- [ ] Weitere kommunale Dienste als optionale Adapter

## Phase 4 – Ökosystem
- [ ] Offene Entwicklerdokumentation und SDKs
- [ ] Community-Governance und transparentes Release-Verfahren
- [ ] Weitere Kommunen und gemeinwohlorientierte Partner
- [ ] Regelmäßige unabhängige Sicherheits- und Barrierefreiheitsprüfungen

## Nicht-Ziele des MVP

- Keine echten Wahlen oder rechtsverbindlichen Abstimmungen.
- Keine produktive Speicherung amtlicher Identitäts- oder Gesundheitsdaten.
- Keine zentrale Bürgerdatenbank.
- Keine Abhängigkeit von einem einzelnen privaten Identitätsanbieter.
